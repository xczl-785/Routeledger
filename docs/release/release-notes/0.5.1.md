# RouteLedger Codex plugin 0.5.1

RouteLedger 0.5.1 completes the local single-user V1 trusted L3 authority foundation. It does not add the Codex three-tier UI or MCP 2026 MRTR.

## Local trusted authority

- Hosts can start the MCP runtime with `--l3-authority-config` or `ROUTELEDGER_MCP_L3_AUTHORITY_CONFIG` and inject a reviewed deterministic policy from an absolute project-external config.
- Config and state paths inside the workspace or RouteLedger root are rejected. Symlinks, non-private local files/directories, binding mismatches, malformed policy, and corrupted state fail closed.
- The exported `installLocalL3AuthorityConfig` host API validates and atomically installs a reviewed candidate. It is not exposed as an MCP tool, so candidate generation cannot install authority.
- The local state store persists policy-use budgets, grant reservations, issued grants, revocation, exhaustion, and exact consumption receipts across MCP process reconstruction without adding a native database dependency.

## Atomic recovery

- Policy budgets are serialized through a host-side lease, so concurrent approvals cannot exceed `maxUses`. Active owners heartbeat the lease; an expired lease is reclaimed only when its owner process is no longer alive. Lock release is bound to its `lockId`, and a revision check prevents a former owner from overwriting newer state.
- A policy-approved operation reservation is idempotent across MCP restart: the exact reserved or issued operation grant is recovered before charging the policy budget, closing the crash window between authority approval and grant issuance.
- Grant consumption and trusted receipt creation now occur in one store transaction. If the following canonical project save fails, retry reconstructs the exact approval artifact from that receipt without consuming another use.
- Consumption replay is bound to the original pending-operation identity as well as its action, target, digest, project, root, subject, and host context; an identical-looking second proposal cannot borrow the first proposal's receipt.
- Rotating a trusted policy digest revokes outstanding delegated grants from the preceding policy while retaining historical receipts for audit and replay verification.

## Deterministic templates

- Core now exposes stable `interactive-safe`, `delegated-balanced`, and `preauthorized` policy builders.
- `recommend_l3_authorization_policy` continues to return a candidate only and now describes the trusted host installation contract and required external path inputs.

## Scope

- This release remains local and single-user. Remote authorization, OAuth identity, organizations, multi-user policy, cross-device revocation, and remote Streamable HTTP are not included.
- Codex's full request-approval / delegated / preauthorized product UI remains the next V3 product slice. MCP 2026 MRTR and non-Codex conformance remain a later V2 compatibility slice.
