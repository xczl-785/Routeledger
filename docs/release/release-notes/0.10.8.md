# RouteLedger Codex plugin 0.10.8

RouteLedger 0.10.8 gives first-time Agents a smaller, progressively disclosed
product model without removing domain, recovery, or audit capabilities.

## Changes

- Groups first-use guidance into Bound Project Context, Route and Current
  Version, Version Lifecycle, Work Classification, Gates and Blockers, and the
  Next Action Contract.
- Clarifies that `complete` records finished implementation while `close`
  means closeout blockers and residual work are settled.
- Defines gates as transition checks and blockers as their concrete unmet
  conditions.
- Makes the returned `recommendedTool`, exact `toolInput`, and host decision
  requirement authoritative for routine Agent navigation.
- Requires a fresh current-state and `next_action` read after a timeout,
  conflict, or unknown result instead of blindly repeating a write.
- Defers route restructuring, exceptional states, closeout auditing, Deferred
  review details, L3 internals, and storage or authorization implementation
  concepts until their matching scenario appears.

## Compatibility

Public tool names, schemas, lifecycle states, authorization rules, canonical
storage, and audit evidence are unchanged. This release changes Agent-facing
onboarding and operating guidance, not the underlying route state machine.

## Release state

The release is fixed by immutable tag `routeledger-plugin-v0.10.8` on `main`.
