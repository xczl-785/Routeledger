# RouteLedger Codex plugin 0.10.6

RouteLedger 0.10.6 repairs five Agent-visible contracts found during an
isolated end-to-end 0.10.5 trial.

## Changes

- Preserves actionable domain errors when optional error details are absent;
  invalid `contentLocale=auto` now returns
  `CONTENT_LOCALE_MUST_BE_CONCRETE` instead of `INVALID_TOOL_OUTPUT`.
- Resolves `nextVersion` from the current Version's persisted direct sibling
  successor, so flattened child Versions no longer contradict the legal
  `advance_to_version` target.
- Requires every non-`close` residual destination to reference an existing
  actionable Todo, Deferred, or Constraint through `destinationRecordId`.
  Close gates validate that handoff instead of reporting success for a record
  that was never created.
- Restores reviewed residual-audit evidence from the committed close proposal
  after a Version closes, while keeping a newer pending proposal authoritative
  during a reopened closeout attempt.
- Separates document-check execution from its conclusion through
  `alignmentStatus` and `safeToTrust`, so a completed check with mismatches
  cannot be mistaken for aligned documentation.

## Compatibility

Public MCP tool names, the JSON-first source of truth, lifecycle states, and
external release-attestation model remain unchanged. Residual items using
`create_todo`, `defer_work`, or `record_constraint` must now materialize their
handoff first and supply its `destinationRecordId`; `destination=close` and
reviewed-empty audits are unchanged. Mission Control remains read-only and its
history-panel default is not changed by this release.

## Release state

The release is fixed by immutable tag `routeledger-plugin-v0.10.6` on `main`.
