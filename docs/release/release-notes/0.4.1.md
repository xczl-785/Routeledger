# RouteLedger Codex plugin 0.4.1

## Release

This patch reduces first-use and ordinary route-progress friction without
weakening the existing L3 approval boundary.

### Highlights

- `init_project` now creates a Project logical root with an empty route by
  default. Callers may explicitly provide `firstVersion` and `initialTodos`
  when the first real delivery node is already known.
- The first approved `create_version` on an empty route becomes current in the
  same atomic commit. Batch creation requires explicit `setCurrentTo` so the
  first current node is never guessed.
- New `advance_to_version` combines switching from a closed current Version to
  its ready direct successor and starting that successor under one digest, one
  approval artifact, one operation ID, and one aggregate save.
- Runtime identity reports plugin SemVer `0.4.1`, its expected immutable tag,
  and the runtime payload digest. Tagged CI emits an external attestation that
  binds the real source commit to runtime and full-distribution SHA-256 values.
- Existing canonical projects retain their historical `initialVersionId`;
  nullable pointers and the SQLite migration add empty-route support without
  rewriting old data.

## Distribution boundary

The release is fixed by immutable tag `routeledger-plugin-v0.4.1` on verified
`main`, tagged CI, and clean Git marketplace verification. It does not publish
`@routeledger/mcp` to npm.
