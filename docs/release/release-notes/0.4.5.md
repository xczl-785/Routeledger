# RouteLedger Codex plugin 0.4.5

## Release candidate

This patch corrects the agent-facing context found by the 0.4.4 fresh-project
evaluation. It is not published until the candidate is merged to `main`, fixed
by the immutable `routeledger-plugin-v0.4.5` tag, and passes tagged release
verification.

### Highlights

- A closed current Version no longer re-runs the pre-close gate after its
  residual audit and close proposal have already been committed.
- A running current Version with open Todos returns `work_todo` instead of an
  unhelpful `none` action. Stable Todo ordering provides deterministic
  navigation and is explicitly not a business-priority claim.
- `get_current_context` and `next_action` expose `currentTodos` for current
  Version work. The legacy-compatible `todos` field remains the all-open-route
  view and declares both scopes under `todoScopes`.
- New projects continue to use the Project itself as the route root;
  `initialVersionId` remains a nullable legacy pointer and is now documented
  explicitly.
- Release acceptance adds a credentialed fresh-host smoke that requires Codex
  to call the installed candidate's native `get_runtime_context` tool. Direct
  stdio runtime checks no longer stand in for host plugin activation evidence.

## Required release evidence

- Full workspace test, typecheck, and lint gates.
- Codex plugin, Git marketplace, packaged MCP, and fresh-host plugin smokes.
- Previous-tag comparison against `routeledger-plugin-v0.4.4`.
- Independent read-only audit before merge.
- Protected-branch PR and required CI before any merge, tag, or publication.
