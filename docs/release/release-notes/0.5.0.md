# RouteLedger Codex plugin 0.5.0

RouteLedger 0.5.0 replaces trust-by-instruction L3 approval with a host-neutral authorization kernel.

## Trusted authorization

- `approve_l3_operation` now requires a cryptographically digested, project/root/action/target-bound grant.
- Codex and other MCP 2025-11-25 clients can supply that grant through structured `elicitation/create`; the tool call suspends until the user accepts, declines, or cancels.
- `.routeledger/l3-authorization.json` can delegate narrowly matched, live-gate-passing operations. Invalid files, binding mismatches, expired rules, and unmatched actions fail closed.
- Session grants remain bound to the same host, client, RouteLedger root, project, action, target, expiry, and use budget.
- Approval artifacts persist grant, source, policy, host, client, and session provenance in canonical JSON and the SQLite read model. Existing artifacts without provenance remain readable as legacy history.

## Safer defaults

- `recommend_l3_authorization_policy` returns a complete balanced candidate and checklist from live route state. It delegates gate-passing start, close, and advance operations while keeping shutdown, reopen, route editing, and current-pointer changes interactive.
- The standalone CLI can no longer self-approve L3 operations. An embedding host must attach a trusted interaction bridge.
- Legacy `decisionRef`, `confirm=true`, chat text, and MCP approval annotations cannot mint authorization.

## Compatibility

- MCP clients without structured elicitation continue to read and propose normally, but interactive L3 approval fails closed unless a valid deterministic policy applies.
- The plugin version moves to 0.5.0 because the approval security model and public MCP tool surface changed.
