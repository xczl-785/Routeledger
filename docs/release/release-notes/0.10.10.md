# RouteLedger Codex plugin 0.10.10

RouteLedger 0.10.10 repairs three Agent-facing response contracts found during
the 0.10.9 lifecycle regression run. The underlying lifecycle, persistence,
and L3 authorization rules are unchanged.

## Changes

- Completes `next_action` and Version transition-guide inputs for empty-route
  Version creation, route-tail Version creation, and atomic Version advance.
  State-known IDs are included directly; genuinely unknown content is declared
  through `requiredInputs`.
- Returns a consistent `confirmation_required` envelope from
  `propose_l3_route_change`, with complete execute, approve, and reject actions.
  A pending proposal's next action now resumes through
  `execute_admitted_proposal` instead of looping back to proposal inspection.
- Recomputes the binding plan after successful activation so its checks and
  risks describe the same post-write state as `filesystemEffects`.

## Compatibility

The generic public L3 proposal response now uses the same confirmation envelope
already used by dedicated Version proposal tools. Segmented approval tools and
the internal proposal entity remain available. Persisted data, lifecycle gates,
host admission, digest validation, and control-plane language are unchanged.

## Release state

This is the 0.10.10 release candidate. The immutable
`routeledger-plugin-v0.10.10` tag is created only after validation and merge to
`main`.
