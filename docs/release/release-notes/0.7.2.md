# RouteLedger Codex plugin 0.7.2

RouteLedger 0.7.2 repairs L3 approval on Codex Desktop when the active task
permission profile is not forwarded to the plugin process. It supersedes the
0.7.1 candidate, whose runtime identity was correct but whose authorization
control plane could still remain unavailable.

## Native Codex admission

- Codex now owns the user-facing high-risk tool boundary. If an
  `approve_l3_operation` or `execute_l3_operation` call reaches RouteLedger,
  the host has admitted that call under the active task permission.
- RouteLedger converts that admission into an exact operation-scoped,
  session-bound, single-use capability. Proposal digest binding, approval
  artifact persistence, consumption receipt verification, live gate checks,
  and atomic commit remain enforced by RouteLedger.
- `CODEX_PERMISSION_PROFILE` is optional diagnostic enrichment rather than an
  authorization prerequisite. Generic MCP interaction, delegated authority,
  and finite preauthorization remain compatibility paths.

## Status and recovery

- `get_l3_authorization_status` reports
  `codex_native_tool_admission_v2` with the `exact_grant_receipt` backend.
- When no permission-profile environment is visible, effective mode reports
  `host_managed` instead of `unavailable`.
- A matching installed version and runtime digest no longer receive false
  update/restart recovery instructions.

The immutable tag remains withheld until merged-main Desktop acceptance.
