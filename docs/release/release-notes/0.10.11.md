# RouteLedger Codex plugin 0.10.11

RouteLedger 0.10.11 clarifies the boundary between stable control-plane text
and human-review project content for lifecycle proposal reasons.

## Changes

- Persists `reasonSource` as `explicit_input`, `system_default`, or
  `legacy_unspecified` across canonical JSON, SQLite, MCP responses, and Mission
  Control.
- Labels system-generated English defaults in `humanReviewText` so reviewers do
  not mistake them for localized project explanations.
- Adds structured `next_action.recommendedInputs` guidance for reasons that
  should be authored in the project's `contentLocale`.
- Accepts explicit human-review reasons through public Version structure tools,
  including creation, insertion, child creation, and reordering.
- Preserves existing operation-digest identity and reads legacy persisted
  proposals without requiring a manual migration.

## Compatibility

Control-plane identifiers and system-default messages remain stable English.
Explicit lifecycle reasons are project content and should follow
`contentLocale`. Existing JSON records decode with `legacy_unspecified`, and
SQLite migration `0011_pending_operation_reason_source` applies the same
compatibility default.

## Release state

The release is fixed by immutable tag `routeledger-plugin-v0.10.11` on `main`.
