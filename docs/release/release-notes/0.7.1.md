# RouteLedger Codex plugin 0.7.1

RouteLedger 0.7.1 supersedes the untagged 0.7.0 Desktop candidate. It gives the
permission-context repair a distinct install/cache/process identity so a test
run cannot silently continue on older 0.7.0 bytes.

## Desktop update repair

- The plugin still forwards `CODEX_PERMISSION_PROFILE` into the bundled STDIO
  server, allowing the Codex adapter to resolve interactive, delegated, or
  preauthorized mode without a separate RouteLedger profile.
- Plugin and runtime identity now report 0.7.1 with a newly generated runtime
  payload digest and expected tag `routeledger-plugin-v0.7.1`.
- Permission-unavailable status and L3 execution failures include executable
  update, Desktop restart, and fresh-task verification actions.
- `get_l3_authorization_status` always returns nullable `profileCompatible`;
  a resolved Codex context reports `codex_permission_adapter_v2` separately
  from the preserved compatibility authorization backend.

## Release discipline

Changed plugin bytes now require a SemVer increase even before an immutable
tag exists. An untagged candidate may already be installed or running, so
same-version candidate repair is no longer considered traceable.

The immutable tag remains withheld until merged-main Desktop acceptance.
