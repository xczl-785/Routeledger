# RouteLedger Codex plugin 0.3.6

## Release candidate

This is the formal 0.3.6 release note for the generated Codex plugin
distribution. It is not evidence of publication: release still requires the
verified `main` commit, immutable `routeledger-plugin-v0.3.6` tag, and tagged
CI.

### Highlights

- The legacy Undo write family has been removed from the MCP registry, CLI,
  and application write paths. Historical Undo documents remain decodable and
  audit-visible, while new work uses Todo, Deferred, and Constraint.
- The generated Codex plugin runtime is synchronized with those source
  changes. Its smoke test now validates the committed bundle without rebuilding
  it first, and proves that `create_undo` is rejected as an unknown tool.
- Ordinary closeout now requires explicit reviewed residual-audit evidence.
  MCP and CLI callers can declare no residuals with
  `{ "status": "reviewed", "items": [] }`; legacy non-empty audit arrays
  remain compatible, while omitted or empty legacy arrays keep the ordinary
  close gate blocked.
- The generated JSON-only plugin runtime now reports its artifact identity on
  MCP initialization and `get_runtime_context`: package version, `json-only`
  profile, plugin version, source-tree state, and a payload digest. Plugin
  `buildCommit` is always `null`; `runtimePayloadDigest` is the authoritative
  content address, so squash/rebase cannot make provenance misleading. The
  bundle continues to omit source-only Mission Control tools.
- `release.json` now records the generated runtime identity alongside the
  distribution and runtime SHA-256 hashes, allowing the release checks to
  replay the complete bundled contract.

## Distribution boundary

0.3.6 remains a Git marketplace plugin candidate only. It does not publish
`@routeledger/mcp` to npm, and it does not turn a successful local build into a
tagged or installed release.

## Historical note

0.3.4 was never published as a release; the plugin line moves directly from
0.3.3 to the 0.3.6 candidate.
