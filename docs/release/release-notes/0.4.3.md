# RouteLedger Codex plugin 0.4.3

## Published release

This patch closes the provenance-discovery, document-drift, and closed-tail
route-continuation gaps reported after the 0.4.2 empty-project regression pass.
It is fixed by immutable tag `routeledger-plugin-v0.4.3` on `main`.

### Highlights

- Plugin runtime identity now exposes a stable detached-attestation locator.
- Tag CI retains its short-lived workflow artifact and also publishes the
  verified attestation as a durable GitHub Release asset.
- The attestation is explicitly an unsigned SHA-256 release manifest. 0.4.3
  does not introduce signing keys, Sigstore, Cosign, or SLSA infrastructure.
- Document-drift suggestions aggregate multiple stale current-Version fields
  into one Todo per file while retaining each warning and reason.
- `当前状态` / `current status` is recognized only near an explicit current-Version
  declaration, avoiding broad README false positives.
- Coverage results include copyable Chinese and English declaration templates.
- A closed top-level tail can receive one append-only successor through either
  `create_version` or `batch_create_versions`. The closed node remains closed
  and current until the ordinary advance flow moves current to a prepared
  direct successor.
- The exception does not permit insertion before a closed node, reordering
  closed history, changing its parent, or adding children under it. A successful
  continuation records `version.successor_appended` for explicit auditability.
