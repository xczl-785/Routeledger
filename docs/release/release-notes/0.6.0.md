# RouteLedger Codex plugin 0.6.0

RouteLedger 0.6.0 introduces the local, single-user V3 authorization broker and three mutually
exclusive authorization modes. It does not add remote or multi-user authority.

## Host-owned authorization

- Authorization profiles, grant budgets, and consumption receipts live in a private host registry
  outside the Agent-writable workspace and RouteLedger root.
- Profiles bind the canonical project, workspace/root digests, subject, host, and trusted client.
  Authorization-effective changes rotate `modeEpoch` and invalidate older uncommitted authority.
- `interactive` accepts only an exact trusted-host user decision; `delegated` evaluates a finite
  deterministic policy; `preauthorized` consumes only explicit finite grants and never silently
  falls back to another mode.
- Commit and revoke use an atomic receipt lifecycle. Revoke-first blocks commit; commit-claim-first
  may finish; exact retries recover after a post-save crash.

## Codex and MCP integration

- MCP startup accepts `--l3-authority-registry` and `--l3-trusted-client-id`. Codex can also
  discover an already initialized registry below its host-owned home without creating authority.
- `get_l3_authorization_status` exposes a read-only profile projection, and
  `recommend_l3_authorization_profile` returns a complete candidate and checklist. Neither tool can
  install, widen, revoke, or mint authority.
- The host broker exposes non-MCP APIs for trusted profile installation, finite preauthorization,
  and immediate access revocation. Empty targets, wildcards, unlimited TTL, and unlimited uses are
  rejected.
- A normal Agent-turn app-server probe records outer approval, MCP elicitation, tool completion,
  and proves that a bare protocol-level acceptance cannot satisfy V3 trusted-user provenance.
  Delegated and preauthorized normal turns complete without an inner prompt; outer Codex tool
  approval remains a separate gate and cannot substitute for the RouteLedger receipt.
- Canonical JSON approval artifacts preserve the V3 profile ID, mode epoch, and profile digest so
  commit-time receipt validation survives a storage reload.

## Current Codex host boundary

Codex app-server 0.147.0 exposes native structured elicitation but does not publish a stable
per-elicitation user-gesture attestation. Consequently, 0.6.0 does not claim that a bare MCP App or
headless elicitation response can install authority or approve an interactive V3 operation. Those
paths fail closed unless the host injects the trusted decision adapter. Delegated and previously
issued preauthorized profiles remain usable through the host-owned registry.

## Compatibility

- The explicit 0.5.1 `--l3-authority-config` path remains available and is never auto-migrated or
  widened. Startup rejects simultaneous V1 config and V2 registry injection.
- Project JSON remains untrusted for authorization. Legacy consumed replay remains exact; legacy
  pending or approved artifacts cannot become new V3 commits.
- V2 MCP 2026 compatibility, remote authority, organizations, OAuth, cross-device revocation, and
  multi-user policy are outside this release.
