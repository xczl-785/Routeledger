# RouteLedger Codex plugin 0.4.0

## Release candidate

This feature candidate introduces the project language contract. It is not a
published release: publication still requires merge to a verified `main`
commit, the immutable `routeledger-plugin-v0.4.0` tag, and tagged CI.

### Highlights

- New projects must initialize with an explicitly user-confirmed concrete BCP
  47 `contentLocale`; missing values, `null`, and `auto` are rejected.
- Legacy projects without `settings.content_locale` remain readable as
  unresolved `null`. Ordinary project writes are blocked until
  `set_project_content_locale` persists a confirmed locale.
- `get_runtime_context` exposes the locale decision state and proposes a value
  from the MCP response language without treating the proposal as consent.
- `responseLocale` localizes explicit system presentation fields while stable
  tool names, keys, enums, error codes, and project/user content remain
  unchanged.
- The JSON codec, SQLite read model, CLI, MCP registry, Codex approval policy,
  operator Skill, generated JSON-only runtime, and migration tests share the
  same contract.

## Distribution boundary

0.4.0 remains a Git marketplace plugin candidate only. It does not publish
`@routeledger/mcp` to npm and does not itself authorize a tag or release.
